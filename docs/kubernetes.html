Identity · secrets · image pulls

Workload Identity path (recommended)

Cluster has oidcIssuerProfile.enabled: true and securityProfile.workloadIdentity.enabled: true — it's ready. Flip values.yaml secrets.backend: kv, set secrets.workloadIdentity.clientID to the MI's client ID, and provision the federated credential mapping system:serviceaccount:flowscope:flowscope → id-aks-corp-eus-01.

FlowScope's internal/secrets picks up FLOWSCOPE_SNMP_KEY_REF=kv:<url> and uses DefaultAzureCredential against the injected token — no static credentials in the pod.

CSI driver path (alternate)

The azureKeyvaultSecretsProvider addon is enabled with rotation every 2m. Use secrets.backend: file in values.yaml and project the secret as a file via a SecretProviderClass. Less code change, but rotation is poll-based, not push.

ACR pulls

Pod images come from acrakscorpeus01.azurecr.io via private endpoint in snet-pep. The kubelet identity (id-aks-corp-eus-01) needs the AcrPull role on the registry — check this before the first deploy, otherwise pods will ImagePullBackOff.

No env-mounted keys in prod

The default secrets.backend: env ships a raw K8s Secret. Fine for dev; use KV in prod. Per CLAUDE.md: master keys must come from Key Vault via Workload Identity, never from env vars.

Architectural callouts

UDP cannot traverse AGIC

Application Gateway is L7 HTTP/HTTPS only. NetFlow / sFlow / IPFIX go through a separate Standard LB provisioned by the ingest Service of type LoadBalancer. Plan IP allowance, NSGs, and exporter destinations against that LB, not AGIC.

ClickHouse DSN doesn't resolve in-cluster

values.yaml ships clickhouse://flowscope:flowscope@clickhouse:9000/flowscope, which is the docker-compose hostname. For AKS, point it at the ClickHouse VM via a headless Service with ExternalName (or a Private DNS A-record). Don't expose the VM publicly.

Single ClickHouse VM

Per cloud-init.yaml, ClickHouse runs on a single VM with a single data disk. There is no replica or cluster. Backup via Recovery Services Vault is essential — and consider migrating to ClickHouse Cloud or a multi-node cluster before scale-out.

Pin to application pool

Without a nodeSelector on FlowScope Deployments, autoscaler can land pods on systempool (and starve cluster add-ons) or metrics (mismatched SKU for ingest). Add agentpool: application selectors.

Zone-spread replicas

Add topologySpreadConstraints with topology.kubernetes.io/zone on api + ingest. Pools are zone-balanced (1/2/3) — without spread constraints, 2 replicas can end up in the same zone.

Network policy in scope

Cluster runs networkPolicy: azure. Default-allow today, but add NetworkPolicies in the flowscope namespace: ingest accepts UDP from anywhere, api accepts TCP only from the AGIC pods, alert accepts no inbound, all egress to ClickHouse + KV + ACR is explicit.

Recommended next steps

  1. Add nodeSelector: {agentpool: application} + topologySpreadConstraints to every FlowScope Deployment.
  2. Add the AGIC ingress template — currently missing from deploy/helm/flowscope/templates/. Annotate for WebSocket support.
  3. Switch secrets.backend default to kv in values-prod.yaml overlay; provision the federated credential on id-aks-corp-eus-01 for SA flowscope:flowscope.
  4. Wire a clickhouse headless Service (or ExternalName) so the in-cluster DSN resolves to the VM's private IP.
  5. Add the service.beta.kubernetes.io/azure-load-balancer-internal: "true" annotation on the ingest Service if exporters live inside the VNet.
  6. Template the snmp and gnmi Deployments to bring the chart in line with the binaries shipped in cmd/.
  7. Add NetworkPolicies for the flowscope namespace — default deny + targeted allows.
  8. Confirm id-aks-corp-eus-01 has AcrPull on acrakscorpeus01, and the Key Vault access policy / RBAC for the flowscope SA.
